❯ /speckit-constitution Python 3.12 managed with uv, FastAPI, Google Gemini     
through the google-genai SDK as the only LLM provider at runtime and in evals.  
Plain Python orchestration with direct function calls; no agent frameworks.     
ORCHESTRATION: a bounded supervisor loop, not a fixed pipeline. A Router plans: 
it returns a typed plan with ordered steps (agent and, for Knowledge, source    
rag or web), the user language as en or pt, and a standalone rewrite of the     
message that resolves references to earlier turns. The supervisor executes each 
step, records a structured observation (status, evidence, unanswered parts),    
and a critic reviews the observations: deterministic rules first, then a        
lite-model check that every part of the user message was answered. The critic   
may replan by adding, retrying or dropping steps; every plan revision and its   
reason is kept in the trace. The loop stops when the answer is complete, at     
MAX_SUPERVISOR_ITERATIONS, or when the per-request budget is spent. When more   
than one step answered, a synthesis step merges their answers into one draft    
that keeps every part. A final Personality step applies the brand voice in the  
planned language and may not add or remove facts, numbers or URLs, checked by   
code in both directions; on violation or failure the draft is returned;         
deterministic refusals skip it. Sources are attached by code after Personality. 
Each agent prompt lives in its own module and states role, scope, output        
format and refusal rules; the current date is injected by code. IDENTITY: every 
endpoint except health and metrics requires a Bearer JWT (HS256 with iss, aud,  
exp, sub and role merchant or operator) verified by code; the chat user_id      
must equal the token subject or the request gets 403; tools receive the         
merchant id from the authenticated principal, never from the LLM; conversations 
and tickets belong to their principal. Tokens are issued only by a CLI          
command, never by an endpoint. Raw user ids never reach logs or prompts: logs   
carry an HMAC pseudonym. MEMORY: conversations persist in SQLite on a Docker    
volume with turns, a rolling summary written by the lite model, and run         
checkpoints; follow-ups are resolved by the Router's standalone rewrite; a      
conversation survives a restart. HUMAN IN THE LOOP: escalation stores a         
checkpoint of the pending run, opens a ticket and returns status                
awaiting_human; operators list, claim atomically and resolve tickets by         
approve, edit or reject; resolving resumes the run from its checkpoint, passes  
the operator answer through Personality, appends it to the same conversation    
and writes an audit entry for every action. GUARDRAILS are deterministic first  
and run before any LLM: a message length limit; a message carrying a full card  
number (Luhn-valid) or a valid CPF is refused, and such values are masked in    
every field before they reach a log or the database; a message that names       
another merchant is refused; prompt-injection heuristics in English and         
Portuguese; the final answer passes a DLP check. Retrieved content and tool     
results are untrusted data, delimited in prompts and never followed or repeated 
as instructions. Unsafe or out-of-scope requests get a polite refusal; domain   
answers must be grounded in retrieved context with cited source URLs, and when  
grounding fails the system does not guess and escalates. MODELS, right model    
per task, all names and thinking levels from environment variables: planning,   
critic, memory summary and Personality use GEMINI_ROUTER_MODEL with thinking    
minimal; answering agents and synthesis use GEMINI_MODEL with thinking low;     
embeddings use GEMINI_EMBEDDING_MODEL; the eval judge uses GEMINI_JUDGE_MODEL   
with thinking high and is never part of the request path. COST: every LLM call  
goes through one client wrapper that records model, latency, prompt, output and 
thinking tokens, cost in USD from a price table in environment variables        
including Google Search queries counted from grounding metadata, logs           
structured JSON with the request_id, applies a timeout and one retry on 429 or  
5xx, preserves complete model content including thought signatures across tool  
turns, and enforces a per-request token budget. Google Search grounding and     
function calling never share a request. Limits are explicit and configurable:   
message length, top-k, tool iterations, supervisor iterations, token budget.    
Every LLM output that drives control flow is parsed into a Pydantic model;      
every tool returns a typed result and handles its own failures; when the budget 
is exceeded or the LLM stays unavailable, the API still returns valid JSON and  
escalates. OBSERVABILITY is implemented, not described: JSON logs with          
request_id, Prometheus metrics at /metrics, alert rules with promtool unit      
tests, a provisioned Grafana dashboard under a compose profile, health split    
into live and ready. EVALS are part of the product: a dataset with the official 
scenarios, compound, adversarial, authorization, multi-turn memory and          
human-in-the-loop flows; a runner against the live API with deterministic       
assertions plus an LLM judge with a typed rubric; judge calibration against     
human labels; retrieval metrics; a sealed held-out set whose hash is committed  
before any code and which nobody opens during the session; the runner exits     
non-zero below thresholds and reports cost. TESTS: every functional requirement 
has an ID (FR-001, FR-002...) and at least one pytest test with the ID in its   
name; unit tests mock the LLM; integration tests call the HTTP API with the LLM 
stubbed at the wrapper. DELIVERY: runs with docker compose up and with plain    
docker build and docker run; non-root image, base image pinned by digest, uv    
lockfile installed frozen, healthcheck, log size limits; GitHub Actions runs    
lint, tests, a container smoke test and promtool on every push, and a live eval 
on tags; secrets only via .env with a committed .env.example. Simplicity over   
abstraction: build only what the spec and this constitution ask for. Each SDD   
phase (constitution, spec, plan, tasks) and each completed task gets its own    
commit on the repository default branch, with no feature or docs branches,      
pushed immediately, so the remote history proves the stages and their times.    
Scope of this phase: write the constitution from this text only, with no web    
research and no API calls; contracts get verified in the plan phase.

command crawls: one level deep from each start page, same host, sequential, 2

  Decisions I made, recorded in research.md:
  - Timezone: business dates use a fixed UTC−03:00. Brazil has no daylight
    saving time, and this avoids adding a tzdata dependency to the slim image.
  - Startup ingestion: runs in a background thread. /health/live answers at
    once; /health/ready only turns ready once the knowledge base has chunks. The
    healthcheck uses Python's urllib (the slim image has no curl) and has a
    long start period to allow for the first ingestion.
  - Hybrid score: cosine similarity, plus 0.10 per matched glossary group (at
    most 0.20), plus 0.10 for chunks that state a rule, then the 0.62 threshold.
    The weights are my default; the retrieval eval will show whether they hold.
  - Operator actions:
    - approve sends the stored proposed answer.
    - edit replaces the escalated part with the operator's text, keeping the
      parts already answered.
    - reject sends a polite rejection carrying the operator's text.
    - All three go through Personality.
  - Code-detected refusals: they never reach a model, so their language is
    picked by Portuguese markers (accents, common words); everything else
    defaults to English.
  - Global-site note: the "not confirmed for Brazil" note is added by code
    whenever a source is www.getnet.net.
  - Container:
    - It runs as uid 10001, and /app/data/state belongs to that user in the
      image, so the named volume inherits the ownership.
    - APP_REV comes from a build argument.
    - The compose file sets name: getnet-multi-agent.
    - Ports are bound to 127.0.0.1.
  - Container early: the Docker step comes right after the first endpoint
    responds in stub mode, not at the end. This follows the engenharia-agentes
    skill.
  - LLM_MODE: it is not in .env or .env.example. Compose sets it from the shell,

  lexical step is only a supplement to the vector candidates.
